# Publishing Workflow

For each three-day cycle:

1. Define the exact coverage window and the publication date.
2. Research material developments across companies, technologies, markets, and infrastructure.
3. Verify claims against primary sources and reliable independent reporting.
4. Include both positive and negative implications, relevant market reactions, and investor relevance.
5. Create `Updates/Provider/YYYY-MM-DD/README.md` with provider, publication date, coverage window, and update type.
6. Create `Data/` and add only the subject folders and files supported by material findings.
7. Add sources alongside the relevant report or in a source register inside that update when useful.
8. Run the quality checklist.
9. Publish the update and verify the committed files on GitHub.

A scheduled research brief is not a GitHub publication. Publishing is complete only after the commit succeeds and the resulting files are verified.
